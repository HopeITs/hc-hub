# X-10 · Extension keeps the same proposal and projects · Dev 2 · S (≤ ½ day) · 1 slice

## Goal
Confirm in the browser that **Extend** on an active proposal keeps the same proposal row, the same number and the same projects, and shows "Extended to …". This is a check, not a feature: if it all holds, the only output is a handoff with screenshots and a short note for X-11 (user story). Fix only a real defect, with a test.

- Review note 9 in `wave3/README.md §0`. D-60. `contracts.md §6` (`ExtendProposal`).
- Upstream: `wave2/handoffs/W-08.md`, `W-33.md` (the `?extend=1` deep link).
- `.ai/rules`: `proposals.md`, `projects.md`, `tests.md`.

## Start state
1. AGENT.md §2 (branch `wave3/X-10-extension-check`, only if a fix is needed).
2. `ProposalExtensionTest` green.

## Check (in the browser, as PR Manager)
1. Pick an active proposal with at least one linked active project; note its number, id, project ids and each project's end date.
2. Extend it (new date, reason, file). Then confirm: same id and number in the URL and header; vitals "Ends … · Extended to …"; the same projects listed, each widened to the new end; new monthly reports generated up to the new end; one status note of kind extension.
3. Extend again with a later date: second note, new date replaces the first.

## Definition of done
- [ ] `wave3/handoffs/X-10.md`: the checklist above with pass/fail and screenshots; one paragraph for X-11 describing the extension in plain words.
- [ ] If anything failed: a test reproducing it in `ProposalExtensionTest`, the fix, green output pasted. Pint clean.

## Stop and escalate to Dev 1
Anything that would change the number, create a second proposal row, or create new projects.

## Do not
Change `ExtendProposal`'s contract. Touch renewal (`CloneProposalForRenewal`): a renewal is a new proposal by design.
