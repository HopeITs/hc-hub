# X-02 · Project = program × governorate, centers as a list · Dev 1 · L (3–5 days) · 3 slices · needs D-69, D-69a, D-69b

## Goal
A project is keyed on **(`city_id`, `program_id`)**. Its centers are a list (`project_centers`, HR ids). Approving a proposal creates or reuses **one project per location row** (city + program) and attaches the row's centers. The monthly report stays one per project per month, so two centers of one program in Aleppo report together, with figures entered once (D-69a). Existing duplicates are merged by a command with a dry run (D-69b).

This is the riskiest item of the wave: it changes the open-project rule, materialisation and the monthly-report key. Run it alone, test on a copy of production.

## Slice 3 · merge command
- `projects:merge-by-city-program {--dry-run}`: groups open projects by (city, program) with > 1 member; target = oldest. Moves centers, proposal links, targets/plan indicators, tasks, milestones, template lines, files. Monthly reports: a month present in only one source moves; a month present in more than one is **not** moved and is listed as a clash for a person to decide. Sources become archived with a note naming the target. One transaction per group; `--dry-run` prints the plan and changes nothing.
- Tests: `ProjectMergeByCityProgramTest` (dry run writes nothing; happy merge; clash month left and reported; idempotent second run).
- Run the dry run on local data and paste it in the handoff.
