# X-09 · Intermediary donor on the proposal · Dev 1 + Dev 2 · M (1–2 days) · 2 slices · needs D-71

## Goal
A new proposal asks, right after the donor: **"Is there an intermediary donor? Yes / No"**. On Yes, a second donor picker. `proposals.donor_id` is always the **primary** donor; agreements, transfers and donor reports stay on it. The intermediary is shown on the proposal header and can filter the register.

## [contract] · authorised by D-71
- `§7`: `proposals.has_intermediary` boolean default false; `proposals.intermediary_donor_id` nullable FK `donors` (`nullOnDelete`), indexed. `Proposal::intermediaryDonor(): BelongsTo`. Invariant: `has_intermediary = false` ⇔ `intermediary_donor_id IS NULL`; `intermediary_donor_id ≠ donor_id`.
- `§6`: `SaveProposal` input gains `has_intermediary: bool`, `intermediary_donor_id: ?int`. The pending-donor rule of W-04 applies to the intermediary exactly as to the primary (one shared rule, not a copy).
- Funding agreements, transfers, donor reports: unchanged, they read `donor_id`.
