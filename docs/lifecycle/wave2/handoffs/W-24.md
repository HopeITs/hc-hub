### Model
```php
// app/Models/Proposal.php
#[Fillable([..., 'notes', 'concept_note', 'requested_budget', ...])]
/** @property string|null $concept_note */
public function activityEvents(): array
{
    return ['status' => 'status_changed', 'concept_note' => 'concept_note_updated', 'name' => 'updated', ...];
}
```
`concept_note` is deliberately **not** in `activityExcludedFields()` (contracts §7, W-24): excluding
it would drop the field from `activityChanges()`, and a concept-note-only edit would then record
nothing at all. It therefore behaves exactly like `notes` — the old and new text land in
`activities.changes`, while the sentence names no text. It sits after `status` and before `name` in
the priority order, so a save that changes the note and the name reads as a concept-note update.

### Action
`App\Actions\Proposals\SaveProposal` — **signature unchanged** (§6). Its `$data` gains one key:
```php
conceptNote?: ?string   // trimmed in normalize(); rules ['nullable', 'string', 'max:20000']
                        // message proposals.concept_note.too_long; blank → null
```
`fillDetails()` writes the column **only when the key is present** (`array_key_exists`), so a caller
that knows nothing of W-24 — `CloneProposalForRenewal`, say — leaves the stored note alone.

### Livewire
```php
// app/Livewire/Concerns/Proposals/ManagesProposalForm (used by proposals/index and proposals/show)
public string $conceptNote = '';
public $conceptNoteFile = null;                      // TemporaryUploadedFile|null
private function validateConceptNoteFile(): void;    // bail|file|max:5120|mimes|extensions|SecureUpload
private function fileConceptNote(Proposal $proposal): void;   // SaveProposalFile, collection concept_note
```
`saveProposal()` validates the upload **before** `SaveProposal` runs (so a refused file creates no
proposal) and files it **after** the save returns (the proposal must exist first). A renewal returns
through `renewProposal()` before either, so neither runs for it. No new upload code: the file goes
through `SaveProposalFile` → `StoredFiles::save()` with `fileDisplayName` empty, which keeps the
upload's own name, exactly as `AddNegotiationNote` does.

```php
// app/Livewire/Concerns/Proposals/ManagesProposalFiles
#[Computed] public function conceptNoteFiles(): Collection;   // filtered from proposalFiles(), newest first
```
It filters the collection already loaded by `proposalFiles()`, so the card costs **no extra query**.
`proposals/show` adds it to `forgetReadings()`, and `saveFile()` / `deleteFile()` unset it too.

## Deviations from contracts.md / the prompt

1. **A renewal has no concept-note field.** `CloneProposalForRenewal::handle()`'s `$data` is a frozen
   §6 signature (`internalProjectNumber`, `name`, `notes`, the two dates), so there is nowhere to put
   the note without changing a contract this prompt does not authorise. The section is hidden for a
   renewal, exactly as Budget and Starting stage already are. **Dev 1:** widening that action is a
   §6 change; say the word and it is a one-line follow-up.
2. **The over-long and wrong-type file cases cannot be reached through the form.**
   `config/livewire.php`'s `temporary_file_upload.rules` already apply the same `max:5120` and
   `FileType` list, so a refused file never reaches the property. The test asserts that refusal
   (`assertSet('conceptNoteFile', null)`) instead of a validation message, and
   `validateConceptNoteFile()` stays as the server-side backstop for any non-Livewire caller. This
   is why `ProposalDetailActionsTest`'s own "disallowed type" case passes — its field is *required*,
   so the refused upload surfaces as `newFile.required`.
3. **One existing assertion changed by intent.** `ProposalDetailTest`'s "each tab shows only its own
   content" asserted the donor's name never appears on the Status tab. The W-24 card names the donor
   there by design, and §7's composite key `(proposal_id, donor_id)` forces an agreement's donor to
   be the proposal's, so the name can no longer tell the two tabs apart. The test now asserts the
   Status tab carries no **link** to the donor page, which is the agreement content it was really
   guarding.
4. **Nested lang keys.** `proposals.concept_note.*` is the prompt's own spelling, and it is the first
   nested group in a file of 500 flat keys (W-10 chose flat for its headings). Flat
   `concept_note_*` keys are a rename away if Dev 1 prefers one convention.
