# I15 · SIM plans and lines

Phase P5 · Model: sonnet · Group H · Needs: I04 · Decisions: D5, D6

## Goal
The organisation's mobile lines (the "Numbers" tab, about 274 lines) live in a register: who holds each line, on which
plan, in which status — so cancelled or idle lines stop costing money unnoticed.

## Sources of truth
1. `docs/inventory/contracts.md §1 (SimStatus + value map), §2 (sim tables), §4, §7, §9`.
2. The assets index page (I05) for the register pattern; the import engine (I10) for the CSV reader and holder resolver — reuse both, do not copy them.
3. `.ai/rules/pages.md`, `ui.md`, `database-migrations.md`, `commands.md`, `models.md`. Handoffs `I04.md`, `I05.md`, `I10.md` (if landed).

## Start state
- `inventory.sims.manage` exists. If I10 has not landed, build the CSV reader usage behind the same small interface I10 will own and note it in the handoff.

## Rules
- Numbers are stored digits-only, normalised to one national format; the unique index is on the normalised value.
- A line's holder is an employee (`employee_id`) or a free-text `holder_label` (shared/office lines). City scoping as for assets via a `SimLine::visibleTo($user)` scope.
- Plans are managed in a small modal list on the same page (operator + name unique).
- Changing status or holder records activity on the line (who, when, from → to).
- `inventory:import-sims {csv} --dry-run`: maps the Numbers tab, creates missing plans from the DropBoxes plan list,
  resolves holders like I10, idempotent on number. Same privacy rule: fixtures are invented; real rows never appear in tests, chat or handoff.

## Build order
1. Tests first, `tests/Feature/Inventory/Sims/`: `SimLineRegisterTest` (403, city scope, filters status/operator/plan/holder,
   search by number, duplicate number rejected, CSV export, query count), `SimImportTest` (dry-run, idempotent, status map, unmatched holder → label).
2. Migrations, models, factories, `SimLinePolicy`, page `inventory.sims.index` with create/edit modal, the command.

## Definition of done
- Both test files pass (paste the line); rollback works. Handoff gives the dry-run **counts** on the real CSV (lines per status), no numbers.

## Stop and escalate
- The sheet holds PIN/PUK or account passwords for lines: they are not imported (D3) — confirm the column list with the developer.

## Do not
- Store PIN/PUK codes or operator portal credentials; build billing or usage tracking.
