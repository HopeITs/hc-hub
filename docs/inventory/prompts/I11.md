# I11 · Import runs and `employee_items` migration

Phase P3 · Model: sonnet · Group F · Needs: I10, I09 · Decisions: D2, D5

## Goal
The hub becomes the master register: the real import has run, its numbers match the sheet, and HR's old
`employee_items` rows live on as assets with custody. This task is mostly operations, with one small command.

## Sources of truth
1. `docs/inventory/contracts.md §9` · plan §7 (risks) · handoffs `I10.md` (dry-run counts), `I09.md`.
2. `modules/Hr/Models/EmployeeItem.php` (or the model behind `employee_items`) and where it is still read.
3. `.ai/rules/commands.md`, `console-commands.md`, `database-migrations.md`.

## Start state
- IT has reviewed the I10 dry-run report and returned decisions for "needs review" and "unmatched holders" rows
  (as corrected CSVs or a mapping file). If not, stop: this task does not start without it.

## Build order
1. `inventory:migrate-employee-items {--dry-run}`: each row → match an existing asset by serial; else create one
   (category from the item, employee's city) and open a custody with the original dates. Idempotent via
   `legacy_source = 'employee_items'` + `legacy_row = id`. Tests `tests/Feature/Inventory/Import/EmployeeItemsMigrationTest.php`
   (created, matched by serial, idempotent, dry-run writes nothing).
2. Mark `employee_items` read-only in the app: remove write paths from the UI only if they exist and are trivial;
   otherwise list them as a follow-up. Do not drop the table.
3. Run book (write it in the handoff, then execute what you are authorised to):
   - local: `--dry-run`, then real, per tab in order city tabs → Communication → Cameras → Study Zone → Extra Laptops → employee items;
   - reconcile: counts per city and status vs the sheet (table in the handoff); list every difference with its reason;
   - staging and production runs are executed **by the developer**: give exact commands, a pre-run DB backup step, and the rollback (`inventory:import` is additive, so rollback = restore backup).

## Definition of done
- The migration test passes (paste the line). Local reconciliation table has zero unexplained differences.
- Run book is complete enough for the developer to execute without questions.

## Stop and escalate
- Counts differ from the sheet and the reason is not a known merge/duplicate.
- Any command would need to run against staging/production from this session.

## Do not
- Run anything against a non-local database, delete `employee_items`, or "fix" sheet data by editing the importer's map without IT's decision.
