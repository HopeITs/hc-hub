# I19 · Whole-module review

Phase P7 · Model: opus (separate reviewer session — not a session that wrote the code) · Needs: I01…I18

## Goal
An independent, adversarial review of the whole Inventory module before production: find what is wrong, prove it,
and hand back a prioritised list. The reviewer fixes nothing above ~20 lines; fixes go back to an implementation session.

## Sources of truth
1. `docs/inventory/contracts.md`, `decisions.md`, every `handoffs/INN.md` (deviations sections first).
2. The diff: `git diff main...HEAD -- modules/Inventory modules/Hr config lang tests/Feature/Inventory database` (or the merged commits).
3. `docs/lifecycle/quality-bar.md`. Skills: `laravel-security`, `security-review`, `performance-optimization`, `hc-ui-ux`.

## Review passes (report each separately)
1. **Authorisation / BOLA** — every route has an ability; every Action starts with `Gate::authorize`; every Livewire
   action that takes an id loads through a scope or parent; city scoping cannot be bypassed with a forged filter or id.
   Try it: write a throwaway Pest test per suspicion, keep the ones that fail.
2. **Invariants** — contract §6, one by one. Search for any write to `status`, holder columns, `city_id`,
   `center_id`, `asset_tag` outside the Actions. Check lock order and after-commit notifications.
3. **Secrets and privacy** — no credential column, fixture, log line or seed; licence key never leaves the reveal
   path; no real sheet data in the repo (`git grep` for serial-like fixtures, phone numbers, names).
4. **Data** — migrations: names, `down()`, encoding, FK behaviour; importer idempotency; `employee_items` path.
5. **Performance** — N+1 on every list (run with query log on 1 000 seeded assets), missing indexes for the real filters, export memory.
6. **UI / RTL / wording** — every page in Arabic at 360 px: mirrored layout, real translations, empty states, error messages from `InvalidAssetState`.
7. **Hub integration** — nothing outside the module edited without a prompt allowing it; Hr tests untouched and green.

## Output
`docs/inventory/handoffs/I19.md`: findings table — id · severity (blocker / major / minor) · file:line · evidence
(failing test or query log) · suggested fix · owner task. Then one line: **go / no-go** for production.

## Definition of done
- All seven passes reported, even when empty. Every blocker has a reproducing test committed to the branch (red is fine).

## Do not
- Rewrite code you disagree with stylistically, or mark "go" with an open blocker.
