# I05 · Assets index page

Phase P1 · Model: sonnet · Group C · Needs: I04 · Decisions: D6

## Goal
IT staff find any device in seconds: one register replacing the five city tabs, filterable and searchable, with a CSV
export of exactly what is on screen. A city IT officer sees only their city.

## Sources of truth
1. `docs/inventory/contracts.md §3, §7`.
2. An existing register page built on `x-ui.data-table` with header filters and CSV export (an Hr employees index or a
   Tracking register) — copy its structure; `app/Support/CsvExport.php`.
3. `.ai/rules/pages.md`, `ui.md`, `views.md`, `views-pages.md`, `components-ui.md`, `navigation.md`, `flux.md`, `css.md`, `views-enums.md`.
4. Skills: `livewire-development`, `fluxui-development`, `hc-ui-ux`. Handoff `I04.md`.

## Start state
- `Asset::visibleTo`, `search`, the factory states and `AssetPolicy::viewAny` exist.

## Rules
- Filters (URL-bound): city, center (depends on city), program, category group, category, status, holder type; search
  box over tag / serial / brand / model. Default: hide `Sold` and `Disposed` (a "show retired" toggle reveals them).
- Columns: tag · category · brand/model · serial · status badge · holder (employee name, center or "Store") · city/center · last verified.
- The query starts from `Asset::visibleTo(auth()->user())`. The city filter only narrows it.
- Export uses the same filtered query and the same columns, streamed; `purchase_price` is included only with `inventory.manage`.
- Paginated server-side (25); eager-load `category, city, center, program, employee`.

## Build order
1. Test first: `tests/Feature/Inventory/Assets/AssetIndexTest.php` — 403 without ability; city scope (other-city asset
   never rendered, even with `?city=` forced); each filter; search by serial and tag; retired hidden by default;
   export has the filtered rows only; **fixed query count** for a page of 25 (pattern: `IndicatorDirectoryTest`).
2. Route `inventory.assets.index`, page `pages/assets/⚡index.blade.php`, nav destination child.
3. Lang keys, status badge colours through one component `x-inventory::status-badge` (reused by every later page).

## Quality bar (this task)
- Works at 360 px and in RTL; empty state and "no results for these filters" state both exist.
- Follow `review-page` thinking: the first screen answers "where is device X / what does center Y have".
