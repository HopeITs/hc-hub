# I18 · Overview page and alerts

Phase P6 · Model: sonnet · Group I · Needs: I16, I17 · Decisions: D9

## Goal
`/inventory` answers "what is the state of our equipment?" at a glance, and the hub nudges the right person when a
handover stays unconfirmed, a shipment is stuck or a licence is about to expire.

## Sources of truth
1. `docs/inventory/contracts.md §7, §8`.
2. An existing overview built from `x-ui.stat-tile` + `x-ui.panel`; an existing alert scanner and its schedule
   registration (`app/Notifications/Alerts/**`, `modules/Tracking/Notifications/Alerts/**`, `ModuleRegistry::addSchedule`), `config/notifications.php`.
3. `.ai/rules/alerts.md`, `recipients.md`, `views-components-notifications.md`, `navigation.md`, `pages.md`, `ui.md`. Skill `dataviz` only if a chart is added.
4. Handoffs `I16.md`, `I17.md`.

## Start state
- The overview route renders the I01 shell; all registers exist.

## Rules
- **Overview** (scope = `Asset::visibleTo`): stat tiles In use / In stock / Broken / Missing; breakdown table by city
  × status (cities in scope only) and by category group; queues: unconfirmed handovers, transfers in transit, pending
  disposals, licences expiring ≤ 30 days (only with `licenses.manage`), SIM lines suspended (only with `sims.manage`).
  Each number links to the pre-filtered register. A `view-own` user is redirected to `inventory.mine`.
- All counts come from grouped queries (no per-city loops); fixed query count.
- **Scanners** (idempotent — one alert per record per threshold, safe to run twice a day):
  `HandoverUnacknowledged` > 7 days → holder, then city IT at 14 days · `TransferStuck` InTransit > 14 days → sender +
  destination IT · `LicenseExpiring` at 30 and 7 days → `licenses.manage` users in scope.
- Notification category `inventory` is user-configurable like the other categories.

## Build order
1. Tests first, `tests/Feature/Inventory/Overview/InventoryOverviewTest.php` (scope, tiles, links, redirect, query count)
   and `tests/Feature/Inventory/Alerts/{HandoverUnacknowledged,TransferStuck,LicenseExpiring}ScannerTest.php`
   (threshold edges with frozen time, recipients, no duplicate on second run, nothing for resolved records).
2. Overview page, scanners, schedule registration, lang.

## Definition of done
- The four test files pass (paste the line). `php artisan schedule:list` shows the scanners. Page checked en + ar, 360 px.

## Stop and escalate
- The alert infrastructure has no per-record de-duplication to reuse.

## Do not
- Add charts beyond one simple breakdown, e-mail digests, or new notification channels.
