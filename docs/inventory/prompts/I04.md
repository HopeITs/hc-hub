# I04 · Asset model, policy and tag generator

Phase P1 · Model: opus · Group B · Needs: I02, I03 · Decisions: D4, D7, D8

## Goal
The asset register exists as data and rules, with no UI: table, model, factory, policy, visibility scope, tag
generator, and the create/update Actions. Every later task builds on this, so the scope and the tag generator must be right.

## Sources of truth
1. `docs/inventory/contracts.md §2 (inventory_assets), §3, §4, §5, §6`.
2. `app/Support/Access/AccessScope.php` and one model that already uses it for city scoping (search `AccessScope::` in `modules/`).
3. `app/Concerns/RecordsActivity.php`; `modules/Core/Models/{City,Center,Program}.php`; `modules/Hr/Models/{Employee,Department}.php`.
4. `.ai/rules/models.md`, `app-2.md`, `policies.md`, `database-migrations.md`, `migrations.md`, `feature.md`, `factories.md`, `observers.md`, `tests.md`.
5. Handoffs `I02.md`, `I03.md`.

## Start state
- The 12 permissions and all enums exist; `inventory_categories` is seeded.

## Rules
- `Asset::visibleTo(User)` is the single definition of who sees which asset (contract §3). No page ever rebuilds it.
- `AssetTagGenerator::next()` allocates inside a transaction with a lock on a per-city+program counter (a small
  `inventory_tag_sequences` table: `city_id, program_id nullable, last_number`, unique pair — add it to this migration set).
  City and program codes come from existing columns; if a city has no code column, stop and escalate.
- `CreateAsset` creates in `InStock`, `holder_type = store`. `UpdateAsset` whitelists descriptive fields only; it
  rejects `status`, holder columns, `city_id`, `center_id`, `asset_tag` even if present in `$data`.
- `purchase_price` is visible/editable only with `inventory.manage` (hide it in `toArray` for others is not enough — expose it through a policy-checked accessor the pages will use).
- Serial numbers are stored trimmed and upper-cased; empty string becomes null.

## Build order
1. Tests first, `tests/Feature/Inventory/Assets/`:
   - `AssetVisibilityTest` — view-all / view-city (own city yes, other city no) / view-own (only open custody; simulate with a factory state) / none.
   - `AssetPolicyTest` — each ability × in-city / out-of-city.
   - `AssetTagGeneratorTest` — format, per city+program sequence, `GEN` without program, no duplicate across 50 sequential calls, tag unchanged on update.
   - `CreateUpdateAssetTest` — 403 without `manage`; guarded columns ignored; duplicate serial rejected; activity recorded.
2. Migrations, model, factory (states: `inStock`, `inUse`, `broken`, `missing`, `sold`, `forCity`), policy, generator, Actions, `InvalidAssetState`.
3. Core bridge relation `Employee::inventoryAssets()` in the provider.

## Quality bar (this task)
- Indexes for the index page filters: `status`, `city_id`, `(city_id, status)`, `employee_id`, `category_id`.
- `visibleTo` compiles to one query without per-row checks; assert the query count in the visibility test.

## Definition of done
- The four test files pass (paste the line); `DatabaseEncodingTest` passes; rollback works.
- Handoff copies the real signatures of the scope, policy abilities, generator and both Actions.

## Stop and escalate
- `AccessScope` cannot express "cities of this user" for a non-Tracking model without changes to `app/`.
- A city or program lacks a stable short code for the tag.

## Do not
- Build pages, custody, or any status-changing Action other than create.
