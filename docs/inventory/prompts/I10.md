# I10 · Import command

Phase P3 · Model: opus · Group F · Needs: I07 · Decisions: D3, D4, D5 · Slices: 2

## Goal
`php artisan inventory:import {tab} {csv} --dry-run` turns each tab of the legacy sheet into clean assets and custody
records, and tells IT exactly which rows it could not understand — so the real run is boring.

## Sources of truth
1. `docs/inventory/contracts.md §1 (value map), §2, §5, §9` · plan §1 and §7.
2. The CSV exports the developer places in `storage/app/private/inventory-import/` (git-ignored). **Never commit them,
   never paste their rows into chat, the handoff or a test.** Build fixtures by hand with invented data that mirror the column layouts.
3. An existing import/seed command with `--dry-run` under `modules/*/Console/Commands` for output style.
4. `.ai/rules/commands.md`, `console-commands.md`, `commands-seeders.md`, `tests.md`. Handoffs `I04.md`, `I07.md`.

## Start state
- The CSV files exist locally (ask the developer if the folder is empty — do not fetch the sheet yourself).
- Assets and custody Actions exist.

## Rules
- One `TabProfile` class per layout (`Support/Import/Profiles`): city tabs (Aleppo, Damascus, Homs, Tartus,
  Latakia), Communication, Cameras, Study Zone Laptops, Extra Laptops. Each maps header names → canonical fields;
  unknown headers are reported, never guessed. Header matching is case/space-insensitive.
- **Cameras profile maps device columns only.** Any column whose header looks like a credential (password, pass, user,
  login, e-mail password, …) is dropped before the row is read into memory structures that get logged. A test asserts
  no such value reaches the database, the report or the log. The GMAILS tab has no profile and is rejected by name.
- `ValueMap` normalises status, category (synonyms + case: "Security camera", "HUB"…), city/center/program names.
  An unmapped value makes the row "needs review"; it is not silently imported as "Other".
- Holder resolution: "CENTER" → center custody; "IT Store" / empty with Not Used → store; "Media Team" → department;
  a person's name → employee by normalised Arabic/English name match (exact after normalisation only; ambiguous or
  no match → `holder_label` kept, asset imported `InStock`, row listed under "unmatched holders").
- Duplicate detection: same serial in several tabs = one asset; the city tab wins for location, other tabs add
  detail (media group, sale, custody history). Rows without serial are keyed by `legacy_source + legacy_row`.
- "Old Users" cells become closed custody rows when names match; otherwise a note on the asset.
- Writes go through `CreateAsset` / `AssignAsset` (with a system actor and historical `handed_at`), so invariants hold.
  Idempotent: re-running the same file updates nothing. Tags are generated in sheet order.
- Extra Laptops rows produce an approved `Disposal` of type Sold only if I13 has landed; otherwise they are reported as "pending sale records".

## Slice 1 — engine + city tabs
`ImportAssets` command, CSV reader (UTF-8 BOM, quoted newlines), profiles for the five city tabs, `ValueMap`, holder
resolver, dry-run report (console table + `--report=path.csv` with one line per problem row: tab, row, column, reason).
Tests `tests/Feature/Inventory/Import/`: `CityTabImportTest` (fixture → expected assets/custodies; dry-run writes
nothing; second run idempotent; unmatched holder kept as label; unknown status → review row).

## Slice 2 — remaining tabs + merge
Communication, Cameras, Study Zone Laptops, Extra Laptops profiles; cross-tab serial merge.
Tests: `CrossTabMergeTest`, `CamerasCredentialSafetyTest`, `LegacyCustodyHistoryTest`.

## Definition of done
- All import test files pass (paste the line).
- A dry run on the real CSVs completes; the handoff gives **counts only** per tab (rows read / assets to create /
  merged / needs review / unmatched holders) and the report file path for IT. No row content.

## Stop and escalate
- A tab's real layout differs from every profile assumption (send the header row names only).
- More than ~15% of rows in a tab land in "needs review": the map needs a human decision, not a guess.

## Do not
- Add a spreadsheet library, call Google APIs, run without `--dry-run` on any shared database, or import SIM lines / licences (I15, I16).
