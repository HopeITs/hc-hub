# Strategies

## Strategy page is a full page; every figure reads allPrograms() (2026-11 redesign)
⚡show is its own page in layouts::desk (no `x-desk.record-sheet`, nothing of the list behind it), styled like programs/show: `.dk-story.dk-strat` with `dk-back` (BackUrl to strategies.index), `dk-crumb` (Strategies › name), eyebrow + `h1.page-title`, status pill + "Year X of Y · Jan YYYY – Dec YYYY", then "Edit details" and a "⋯" menu (Link programs, Delete strategy — disabled with its reason in words while the strategy has programs or pillars). After a delete, `strategyDeleted()` redirects to strategies.index. Below the head: one paper statement (`.dk-strat-sum`) with `x-strategies.year-line`, `x-strategies.verdict`, the figures (`_show-figures`, `.dk-sfigs`: Pillars, Programs, Projects, Funding, "N/M have a YYYY plan") and `x-strategies.attention-list`, then "How the strategy is built" (`_show-pillars` + `_show-pillar-program`).

There is no programs table and no pagination any more (no programs(), sortBy(), sort/direction, WithPagination, coverage ring or year dots). Every count reads the unpaginated `allPrograms()`; the pillar rows read `pillarGroups()` (ManagesStrategicPillars), which reads allPrograms() too. `plannedYears()` (one query: "program:year" for plans with at least one plan indicator) feeds `currentYearPlans()` — null unless the strategy runs this year and the viewer has annual-plans.view — which drives the plan figure, the no-plan attention line and the "No YYYY plan" row status. `rollup()` is StrategyRollup::for() for this one strategy; `programPaces()` is StrategyRollup::programPace() per program; `programStates()` picks each row's status (no plan → falling behind → on pace → no progress yet). `attention()` = StrategyAttention::items() (the list's four lines) + StrategyAttention::programsBehind() (names up to 3, then "and N others"; links to indicators.index?strategy&focus=offtrack, i.e. amber + red targets, the same set programPace counts as not on pace).

## Strategies list: current blocks, quiet upcoming list, paginated past list (2026-11 redesign)
⚡index has three sections, picked by the All · Active · Upcoming · Completed tabs (`status` '' / active / upcoming / completed via filterByStatus()): **Current strategies** (one `.dk-cstrat` per active strategy: name, `x-strategies.year-line`, `x-strategies.verdict`, four figures, `x-strategies.attention-list`), **Upcoming** (quiet rows: starts in N months · X of Y programs ready) and **Past** (quiet rows with Open, plus Link programs / Delete for a strategy with nothing linked). No count badge, no timeline, no table, no icon-only buttons. The search box shows only when there are more than 6 strategies (or a search is already typed).

portfolio() still builds the whole sorted Collection in memory (status comes from the years, not expressible as one ORDER BY) and returns it split: `current` and `upcoming` are unpaginated Collections (there are few), `past` is a hand-built `LengthAwarePaginator` (15 per page, pageName 'strategiesPage', `$pastList->forPage(...)`); only the past list and its `<flux:pagination>` read the paginator. flux:pagination needs only the LengthAwarePaginator contract, so the manual paginator works. `status_counts` (tab counts) and `last_ended_year` (the "no active strategy" sentence) come from the search-filtered list, `total_count` (search box threshold, "strategies exist") is unfiltered.

rollups() runs StrategyRollup::for() only for `current` (the only blocks with figures); readiness() calls StrategyRollup::planReadiness() once for current (this year) + upcoming (their start year). StrategyAttention::items() turns one rollup + readiness into the attention lines. search/status changes call resetPage('strategiesPage') (updatedSearch(), filterByStatus(), resetFilters()).

Create / edit / delete / link-programs live in the traits App\Livewire\Concerns\Strategies\{ManagesStrategyForm, DeletesStrategy, LinksStrategyPrograms} with their modals in `_strategy-form-modal`, `_delete-modal`, `_programs-modal` (shared with the strategy page). DeletesStrategy::strategyDeleted() is the after-delete hook (no-op on the list).
